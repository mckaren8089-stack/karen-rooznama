# چهار پایه فنی روزنمای کارن — وضعیت اجرای ۰.۳

## ۱. موتور تاریخ
- تبدیل هجری شمسی/میلادی در `core.mjs` با `Intl.DateTimeFormat` و بررسی تاریخ نامعتبر.
- منطقه زمانی امروز: `Asia/Tehran`.
- آزمون رفت‌وبرگشت تاریخ‌های ۲۰۲۴ تا ۲۰۳۰ در GitHub Actions.
- تحقیق بعدی: سنجش تفاوت‌های مرزی آغاز سال در بازه‌های دور، با مرکز تقویم دانشگاه تهران.

## ۲. مناسبت‌ها و منبع رسمی
- منبع منتشرشده: **PDF رسمی سالانه** در `https://calendar.ut.ac.ir/documents/2139738/7092644/Calendar-1405.pdf`.
- در بررسی اولیه، API رسمی و مستند برای مصرف زنده پیدا نشد؛ **هیچ API فرضی وجود ندارد**.
- بسته هر سال با `year`، `source`، `status` و ردیف‌های مستقل `month/day/title/holiday/category` ذخیره می‌شود.
- داده فعال ۱۴۰۵ در `data/years/1405.json` **خروجی پالایش‌شده از تمام ۱۲ ماه رسمی** است و برچسب `reviewed-nonreligious` دارد. گزارش ممیزی PDF: ۳۶۵ سطر روزانه، ۱۸۹ روز مناسبت‌دار در منبع، ۲۱۰ رویداد غیرمذهبی در ۱۴۴ تاریخ، و ۴۵ روز با مناسبت صرفاً مذهبی که از خروجی حذف شدند.
- ردیف‌های مذهبی، یا ردیف‌های ترکیبی مذهبی، هنگام ورود به خروجی حذف می‌شوند؛ مناسبت‌های ملی/فرهنگی/تاریخی جداگانه حفظ می‌شوند.
- **بدون داده معتبر برای یک سال، مناسبت‌های همان سال خالی می‌مانند**؛ داده ۱۴۰۵ به سال‌های دیگر سرایت نمی‌کند.
- `scripts/check-official-source.mjs` و Workflow `check-official.yml` وضعیت دسترسی به PDF را دوره‌ای بررسی می‌کنند؛ در صورت موفقیت نیز هیچ داده تأییدنشده‌ای خودکار منتشر نمی‌شود.
- ورود و ممیزی رویدادهای غیرمذهبی ۱۴۰۵ **انجام شد**؛ اما بررسی حقوق و شرایط بازنشر PDF و داده‌های مشتق‌شده همچنان جدا از مجوز کد باز است.

## ۳. یادداشت‌ها
- یادداشت‌ها با تاریخ شمسی دقیق در `localStorage` همان دستگاه نگهداری می‌شوند؛ کلید `karen-rooznama-notes-v1` **برای حفظ یادداشت‌های قبلی تغییر نمی‌کند**.
- دسترسی همه یادداشت‌ها از یک زبانه، نشان روی روز، ویرایش، تأیید قبل از حذف، پشتیبان و بازیابی JSON.
- خروجی/ورودی JSON محلی است؛ نه سرور و نه GitHub هیچ یادداشت شخصی دریافت نمی‌کنند.
- اصلاح خطای حفظ یادداشت‌های هم‌متن هنگام بازیابی.
- موارد باز: تست واقعی روی اندروید، عمر داده در حالت نصب PWA، همگام‌سازی اختیاری و پشتیبان خودکار (نیازمند تصمیم درباره خدمات و حریم خصوصی).

## ۴. طراحی و معماری رابط
- طراحی گراک دیگر مبنای هویت محصول نیست؛ پایه جدید روزنما با نشان اختصاصی «ر»، رنگ سبزآبی و الگوی موبایل‌اول تنظیم شد.
- متن‌های فنی زیر تقویم حذف شده و فقط در مستندات توسعه نگهداری می‌شوند.
- نمای تقویم، تبدیل تاریخ و یادداشت‌ها مستقل از منبع مناسبت‌ها هستند.
- تغییر اصلی بعدی طراحی: مطالعه و انتخاب طرح نهایی؛ **ظاهر فعلی هنوز طرح نهایی برند نیست**.

## خط‌قرمزهای توسعه
- کل خدمات پایه رایگان؛ GitHub Pages و Actions استاندارد، بدون خرید دامنه.
- هیچ خطای فنی یا وضعیت توسعه در انتهای رابط کاربر چاپ نمی‌شود.
- نه تعطیلات و مناسبت‌های ساختگی، نه اعلام اتصال بلادرنگ به PDF.
- تصمیم لایسنس هر دو مخزن روزنما و کارن فیوز باز است.
