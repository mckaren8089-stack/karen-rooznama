## محدوده

## تغییرات اجرایی
- **حفظ داده قدیمی:** کلید فعلی `karen-rooznama-notes-v1` بدون تغییر باقی مانده است؛ هیچ مهاجرت اجباری یا حذف حافظه انجام نشده.
- **نوشتن محافظت‌شده:** افزودن، ویرایش، حذف و import ابتدا روی یک کپی محاسبه می‌شوند. تنها بعد از موفقیت `localStorage.setItem`، تغییر در UI قطعی می‌شود.
- **نسخه پیشین:** مقدار معتبر فعلی، پیش از هر تغییر، در `karen-rooznama-notes-previous-v1` نگه داشته می‌شود. وقتی فضای ذخیره پر باشد یا نسخه ایمنی قابل ثبت نباشد، تغییر جدید اعمال نمی‌شود.
- **قفل ایمن خطا:** JSON خراب یا داده‌ای که خوانده نمی‌شود بی‌صدا `{}` تعبیر و بازنویسی نمی‌شود. کاربر امکان دانلود داده خام و، با تأیید صریح، بازیابی نسخه قبلی یا JSON دستی را دارد.
- **زبانه‌های هم‌زمان:** تغییرات `storage` مشاهده می‌شوند؛ هنگام ذخیره، آخرین متن ذخیره‌شده با snapshot زمان بارگیری مقایسه می‌شود تا تب قدیمی، نسخه جدیدتر را بی‌صدا بازنویسی نکند. در مرورگرهای پشتیبان `Web Locks API`، تغییرات برنامه در یک قفل اختصاصی سریالی می‌شوند.
- **پشتیبان دستی:** JSON خروجی همچنان برای انتقال یا بازیابی روی گوشی دیگر در دسترس است. پیام UI اکنون روشن می‌کند که درخواست دانلود ارسال شده است، نه اینکه ذخیره فایل حتماً تأیید شده.
- **آفلاین:** ماژول `notes-store.mjs` به پیش‌کش PWA اضافه شده و Cache Version به `karen-rooznama-v0.4.0` تغییر کرده است.

## مرز حفاظت
- این نسخه **همگام‌سازی ابری، بکاپ خودکار مستقل از دستگاه یا رمزگذاری سرتاسری** ایجاد نکرده است.
- دو نسخه موجود در `localStorage` هر دو ممکن است در اثر پاک‌شدن Site Data، حذف اطلاعات مرورگر، نقص دستگاه یا تغییر Origin از بین بروند. بنابراین فایل JSON خارج از مرورگر همچنان ضروری است.
- خطای `QuotaExceededError` احتمال دارد در حافظه محدود زودتر رخ دهد؛ در این حالت حفاظت از نسخه قبلی عمداً بر نوشتن داده جدید اولویت دارد.
- بدون بررسی مستقل روی گوشی کاربر، موفقیت تست Node و GitHub Actions به‌معنی تأیید کامل تجربه اندروید نیست.
